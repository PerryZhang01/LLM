四路残差 mHC

embedding 被原样复制 4 份，成为 [T, 4, 5120] 的残差流，同时配一个 one-hot 的 pre_mix。 每个子层只看 4 路加权合成的 1 路；它用自己的输入残差预测下一个子层的合成权重，自己的输出则欠着，留给下一个接缝写回。 这样「写回上一子层 + 预测系数 + 合成 + RMSNorm」能在一个 kernel 里一遍做完。本章把这条链从展开、接缝、Sinkhorn 到栈末尾逐步拆开，配一组算得出数的例子。

[T, 4, 5120]残差形状，bf16
40 KiB每 token 残差（原来 10 KiB）
24每子层混合系数 = 4 + 4 + 16
[24, 20480]hc_fn，FP32
20Sinkhorn 迭代次数
80接缝数，2 个要拆成两次 launch
从 embedding 到 4 路延迟 pre一个接缝的四步 系数与 Sinkhorn第 0 层数值推演栈的末尾 为什么是 4 路读码路线

展开

展开没有参数：复制 4 份，再给一个 one-hot 的 pre

atom/model_ops/deepseek_v41/mhc.py:103 的 from_embeddings 只有两行： hidden.unsqueeze(-2).expand(…, 4, 5120).contiguous() 得到残差，torch.zeros(…, 4) 再把第 0 列置 1 得到 pre_mix。 expand 本身只是 stride 为 0 的视图，.contiguous() 才把 4 份真正写出来。

展开之前已经发生的事

TP all-reduce 与 Engram 的分叉

VocabParallelEmbedding 先在 TP 组里 all-reduce 出完整的 [T, 5120]，再复制，所以 4 份在每张卡上都是完整的。 Engram 的查表在这之前就由 begin_forward 发到旁路 stream（第 3 章）。图像请求走 inputs_embeds，视觉 embedding 用同样的方式展开。

DSpark 的写法

一个 Triton launch 写出同样的字节

草稿块不调用 from_embeddings，而是 atom/model_ops/deepseek_v41/dspark.py:258 的 build_block_state： 只 embed 每个请求的 anchor，其余列是同一个 noise token，它的 embedding 缓存一次。 kernel 直接写出 [B, width, 4, H] 的 4 份副本和 one-hot 的 pre，TP all-reduce 的行数少了 block 宽度那么多倍。

原生 runtime 的 _EarlyLayers（atom/models/deepseek_v41/runtime.py:199）会先把 hidden 加一个 [None] 维， 所以那里的残差是 [1, T, 4, 5120]；编译边界上再用 _rows_first 去掉这一维。

延迟 pre

每个子层用自己的输入预测下一个子层的 pre，所以第 0 个子层要人为补一个

把 atom/model_ops/deepseek_v41/mhc.py:214 的 apply_sublayer 写成公式。第 k 个子层（每层 attention、FFN 各算一个）的输入状态是 (R_k, p_k)： 

(p_{k+1}, post_k, comb_k) = predict_mixes(R_k; hc_fn_k, hc_scale_k, hc_base_k)   # 用本子层的权重，预测的是下一个子层的 pre
x_k      = Σ_m p_k[m] · R_k[m]                                        # collapse 用的 p_k 来自上一个子层
out_k    = sublayer_k( norm_k(x_k) )
R_{k+1}[j] = Σ_i comb_k[i, j] · R_k[i]  +  post_k[j] · out_k             # expand_residual / aiter.mhc_post

与 DeepSeek-V4 的区别

V4 论文 §2.2 的式 (1) 里，第 l 层的输入映射 Al 由同一层的 Xl 算出；ATOM 的 V4 也是这样（hc_pre 用自己的输入残差算自己的 pre）。 V4.1 把 A 推迟了一个子层：本子层 collapse 不再依赖本子层的投影和 Sinkhorn。代码注释的原话是 “V4's single aiter.mhc_pre cannot serve this model”，所以 V4.1 另写了 atom/model_ops/deepseek_v41/mhc_pre_delayed.py:97 的 pre_delayed。

接缝

一个接缝四步：补写、预测、合成、归一化，一个 kernel 做完

子层之间那一段计算在代码里叫 seam。Block.prepare_attention（atom/models/deepseek_v41/model.py:140）和 prepare_ffn（atom/models/deepseek_v41/model.py:168）各调用一次 pre_delayed，后者落到 atom/model_ops/deepseek_v41/mhc_pre_delayed.py:185 的 v41_mhc_pre_delayed，是一个对 Dynamo 不透明的 custom op。

  1. 补写上一子层的输出。上一子层留下 out [T,5120]、post [T,4]、comb [T,4,4]，这里算 R'[j] = Σ_i comb[i,j]·R[i] + post[j]·out，得到新的 [T, 4, 5120]。
  2. 预测本子层的系数。把 R' 摊平成 [T, 20480]，乘 rsqrt(mean(x²) + 1e-20)，再乘 hc_fnᵀ 得到 mixes [T, 24]，经 hc_split_sinkhorn 拆成 pre、post、comb。
  3. 合成 1 路。用上一子层带来的 p_k 对 4 路加权求和，得到 [T, 5120]。
  4. 本子层的 RMSNorm。权重是 attn_norm 或 ffn_norm（[5120]）。attention 一侧在 HIP 后端上可以顺带输出 MXFP8 副本（hc_fuse_quant，atom/model_ops/deepseek_v41/mhc_pre_delayed.py:61），直接喂给 wqkv_a，省一次量化。

例子 · 第 0 层 attention 这个接缝

  1. pending = None，跳过补写。
  2. 用第 0 层的 hc_attn_fn 对 4 份相同的 R₀ 做投影与 Sinkhorn，得到下一子层的 p₁，以及 attention 自己的 post₀、comb₀。

栈的末尾

V4.1 没有 hc_head：最后一个 FFN 子层预测出的 pre 就是收尾权重

动机

为什么要 4 路：残差宽度成了一个和 hidden 无关的新维度

HC（Zhu et al., 2025）

把残差流加宽

残差从 Rd 加宽到 Rn×d：Xl+1 = BlXl + ClFl(AlXl)。 层内仍只看 d 维，注意力和 MoE 不用改。论文的说法是它「把残差宽度和 hidden size 解耦，提供一个互补的扩展维度」，且 n 远小于 d，计算开销很小。

mHC（Xie et al., 2026）

加约束解决多层叠加的不稳定

论文原话：普通 HC “training will frequently exhibit numerical instability when stacking multiple layers”。 mHC 把 B 投影到双随机矩阵（Birkhoff 多面体），A、C 用 sigmoid 约束。

代价量级出处
残差显存与带宽4×：每 token 40 KiB按形状算
每个子层多一次 GEMV[T, 20480] × [20480, 24]，访存为主按形状算
训练时的墙钟开销6.7%（融合 kernel + 重计算之后）V4 论文 §3.5.2

为什么偏偏是 4

V4 论文给 Flash 和 Pro 都设 n_hc = 4，没有给 n 的消融；不同 n 的比较在 HC、mHC 原论文里，本组文档没有核对。 ATOM 推理端的 kernel 也只特化了 4 路：expand_residual 只在 hc_mult == 4 时走 aiter.mhc_post； pack_mhc_fn 要求 fn.shape[0] == 24、fn.shape[1] ∈ 4 × {4096, 5120, 6144, 7168}。换成别的 n 只能回退到 torch / Triton。

读码坑

residual 字段不一定是「当前」残差

pending 非空时，residual 是补写 post 之前的值。要读真实残差必须先 settle()；Engram 与 DSpark 截取层输入时都这么做。

读码坑

Triton collapse 刻意关掉 FP 融合

collapse_streams（atom/model_ops/deepseek_v41/mhc.py:55）用 enable_fp_fusion=False，乘和加分开做，才能和 torch 的写法逐位一致。
