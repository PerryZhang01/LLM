CSA2 注意力骨架

40 层的注意力是同一个类 Attention，同一套 Q / O 投影，同一个双源稀疏注意力 kernel。 每个 query 看到的 key 只有两路：从全局压缩 KV 里挑出的至多 512 行，加上本层自己的最近 128 行；两路和一个可学习的 sink 一起做一次 softmax。 WINDOW、FULL、REUSE、REINDEX 四种模式只是在这八步里少跑几步、或者把某一步的结果借给别人。

一句话

每个 query 只看两路 key：选中的全局行和本层窗口

V4 论文 §2.3.1 的 CSA（Compressed Sparse Attention）分三步：把每 m 个 token 的 KV 压成一行；用 lightning indexer 给压缩行打分，只保留 top-k； 再拼上一小段滑窗的原始 KV，补局部细节。V4.1 的 CSA2 保留了这个骨架，下图是第 2 层一个 decode token 实际看到的东西。

CSA2 相对 V4 的 CSA 改了五处。V4 一列的数字取自本地 DeepSeek-V4-Flash/config.json：

为什么 indexer 不切

top-k 之前必须先把 32 个头加起来

schema 注释（atom/models/deepseek_v41/weights.py:180）：“Replicate the small indexer: scores must reduce all its heads before top-k, without a context-sized all-reduce on every layer.” 按头切到各卡，每层都要对一个「上下文长度宽」的分数矩阵做一次 all-reduce。

两处合并

wq_a 与 wkv 合成一个 GEMM

wqkv_a（atom/models/deepseek_v41/attention.py:239）一次读输入、一次量化就出两个 latent； DualRMSNormMXFP8（atom/models/deepseek_v41/attention.py:262）把 q_norm 和 kv_norm 并成一次 launch，q 侧顺带出 MXFP8 副本，主 query 和 indexer 的 wq_b 都直接吃它。

数据流

八步，三条 stream，三个 eager 断点

以功能最全的 FULL 层为准（其他模式是它的子集）。D 只依赖 h，所以在 forward 一开始就发出去；E 依赖 A 的 qr，也依赖 D 刚写下的 index key； 主路径上的 B、C 和两条旁路互不依赖，可以并行。

  1. A · Q/KV 下投影（atom/models/deepseek_v41/attention.py:321 project_qkv）：一次 FP8 GEMM 得到 q_lora [T, 1280] 和 kv [T, 512]，再一次 launch 做两边的 RMSNorm。
  2. B · 主 query：wq_b(qr) → [T, 64, 512]。这是唯一按头切的投影，TP4 下每卡算 16 个头。
  3. C · RoPE + 写窗口（atom/model_ops/attentions/deepseek_v41/cache.py:787 rope_quant_window）：q、kv 的末 64 维旋转，kv 量化成 528 B 的 MXFP8 行。decode 时这一行直接写进本层 ring；prefill 时只产出不写，因为本 chunk 的 query 还要读 ring 里的旧行。
  4. D · Compressor（atom/models/deepseek_v41/attention.py:299 _compress_batch）：本 batch 跨过的每个组边界产出一行压缩 latent，写进 main_owner；同一个 latent 在 RoPE 之前过 wk，写进 index plane。第 6、7 章细讲。
  5. E · Indexer（atom/models/deepseek_v41/attention.py:393 _select）：32 头 ReLU 加权打分，取 top-512 写进 step.selected[layer]。第 6 章细讲打分，第 9 章讲候选块内重选。
  6. F · 下标（atom/model_ops/attentions/deepseek_v41/cache.py:911 attention_indices）：把选中的逻辑行翻译成池里的物理行，拼上窗口行，生成 CSR 列表。同一下标组（ratio、owner、top-k 来源都相同的连续层）只在组首层建一次。
  7. G · 稀疏注意力（atom/models/deepseek_v41/attention.py:447 _attend）：FP8 池走 AITER 的 mla_sparse_prefill_v41（atom/model_ops/attentions/deepseek_v41/fp8_attention.py:31），BF16 池走 V4 的 sparse_attn_v4_paged_2src，FP4 主池走 packed_prefill / packed_decode。
  8. H · 输出（atom/models/deepseek_v41/attention.py:334 _project_out）：inverse RoPE 与 MXFP8 量化一次完成，再做分组 wo_a 与 wo_b。prefill 在这之后才 write_window（atom/model_ops/attentions/deepseek_v41/cache.py:878）。

位置编码

512 维里只转最后 64 维，两张频率表按层选

前 448 维不旋转，承载内容；最后 64 维按 GPT-J 的相邻成对方式旋转（atom/model_ops/deepseek_v41/rope_window.py:32 的 _rotate_head 从 D - ROPE 处开始）。 选哪张表只看 ratio：atom/models/deepseek_v41/model.py:381 的 rope = self.global_rope if spec.ratio else self.window_rope。

为什么输出还要转回去

K 和 V 是同一个已经旋转过的 512 维向量。attention 的输出 o = Σ p_j · v_j 里，每个 v_j 的末 64 维带着各自位置 pos_j 的旋转。 H 步先按 query 的位置 t 反向旋转一次（inverse_rope_group_quant），末 64 维就变成只依赖相对位置 pos_j − t 的量，然后才进输出投影。 这一步和 MXFP8 量化合在一个 kernel 里，省掉一次读写。

输出投影

64 个头分 8 组，每组一个 4096 → 1024 的小矩阵

wo_a 不是一个 32768 → 8192 的大矩阵，而是 8 个独立的 4096 → 1024：第 g 组的 8 个头只投到自己那 1024 维。 权重以 ColumnParallelLinear 的身份加载（atom/models/deepseek_v41/attention.py:273），再 view 成 [8, 1024, 4096] 交给 batched GEMM。

例子 · 一个 decode token 的输出投影要算多少

按形状估算，单 token、整模型宽度：wo_a 是 8 × 4096 × 1024 ≈ 33.6 M 次乘加，wo_b 是 8192 × 5120 ≈ 41.9 M 次。 如果 wo_a 是一个不分组的 32768 → 8192 矩阵，会是 268 M 次，正好是 8 倍——分组 LoRA 省下的就是这 7/8。

两种平面

index key 是给打分用的缩略 key，attention 从不读它

每个 KV owner 的每个压缩行 s 同时存两样东西：main_owner 第 s 行是 512 维的 KV，attention 用；index plane 第 s 行是 128 维的 index key，Indexer 用。 两者共用同一个 block id、同一张 PAGE 表，只是存在池里的不同区域。

四种模式

四种模式都是 A–H 的子集，差别全在 D、E、F

A、B、C、G、H 四种模式都跑，而且做法完全相同（除了 RoPE 表）。差别只在三处：有没有 Compressor（D），有没有 Indexer（E），以及下标里的源 1 从哪个池取、按谁的选择取（F）。

query窗口 KV全局 KVindex keytop-k 选择

两路源

prefill 的第二路是本 forward 自己的 KV，decode 的第二路是 ring

G 步的 kernel 签名固定是「池 + prefix 列表」加「第二个源 + 它的列表」。prefill 和 decode 往这两个槽里放的东西不一样，分界由 atom/model_ops/attentions/deepseek_v41/indices.py:276 的 splits_window 决定： step.decode and not geometry.packed。

源 1（pool + prefix）源 2ring 何时写
prefill选中的全局行 + 本层 ring 里 chunk 起点之前的窗口行，每层一份本 forward 刚算出的 KV（extend），一组层共用一份列表，每行最多 128attention 之后，write_window 只写每个请求最后 ring_slots 行
decode（非 packed）只有选中的全局行，整组共用一份本层 ring 的视图 ring_view（atom/model_ops/attentions/deepseek_v41/cache.py:942），窗口行列表全组共用C 步就写，G 步读到的窗口已含当前 token
decode（FP4 packed 池）一份带标记的列表，选中行与窗口行混在一起不用C 步

窗口行的时序与地址公式见 第 5 章。
