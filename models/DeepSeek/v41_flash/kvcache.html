KV Cache 存储层

V4.1 的所有缓存住在每张卡上的一整块 uint8 arena 里：前面按页买，装 4 个 owner 的全局 KV 和 index key，随历史增长； 后面按请求买，装 40 层窗口 ring、compressor 尾巴和 Engram 游标，随并发增长。前缀缓存只认前面那一半——命中的页直接挂进新请求的块表， 后面那一半从不共享，要么重算（第 11 章），要么从镜像拷回来。这一章把每块区域的形状、地址和读写时机讲清楚。

分区

一块连续的 uint8 arena：前面按页买，后面按请求买

后端只声明两类条目（atom/model_ops/attentions/deepseek_v41/backend.py:367）：page_pool(paged_bytes) 和 state_pool(STATE_SLOT_CLASS, state_bytes, entries_per_req=1)。通用的显存规划先给 STATE 留 max_num_seqs × 1 个槽（atom/model_ops/attentions/pool_layout/sub_pool_spec.py:221），剩下的显存全部按 paged_bytes 切成页。 然后 atom/model_ops/attentions/deepseek_v41/cache.py:48 一次分配出整块清零的 uint8 张量，所有区域都是它的 view。

为什么必须是一整块

页行和窗口行共用一个基址

注意力的下标是一串 int32 行号，同一份列表里既有选中的全局行，也有窗口行。几何把第 L 层 ring 的起点写成「页区末尾之后的绝对偏移」（atom/model_ops/attentions/pool_layout/v41_pool_geometry.py:395），所以 PAGE 和 STATE 拆不开。

为什么 PAGE = 128

块表要小，复用粒度要细

块表是 [max_num_seqs, max_model_len / block] 的 int32，每个 forward 都要拷：百万上下文下 block 16 是 134 MB，128 是 16.8 MB。一页又是前缀缓存的 hash 块，128 正好等于窗口（atom/config.py:2776）。

硬约束

PAGE ≥ window − 1

encoder replay 靠往回退一页重建窗口，页比 127 短就盖不住，validate_runtime_config 直接拒绝（atom/models/deepseek_v41/config.py:414）。这条比「ratio 2 的 owner 每页行数要是 tile 整数倍」那条严得多。

PAGE

一页 = 4 个 owner 的 320 行主 latent，加上它们分开存的 index 行

page_fields（atom/model_ops/attentions/pool_layout/v41_pool_geometry.py:266）按 owner 顺序在页内排四个字段： ratio 2 的 owner 每页 64 行，第 20 层 128 行，合计 320 行。index 行不进页，而是每个 owner 一整块区域、按页连续排（region-major）， 这样一个 8 行的 tile 能被 block id 单独寻址——候选块之所以能直接当块表用，靠的就是这一点（第 9 章）。

每张卡各存一整份

KV 只有一个头，没法按头切

wqkv_a、Compressor、Indexer 的 key 一侧都是复制的线性层，每个 TP rank 都算出完整的 512 维 latent，写进自己的池。所以上表的每 token 字节数就是每张卡的开销（按构造推断，没有跑 profile 核对）。

量级

全局 KV 很便宜

部署默认下 100 万 token 的上下文约 1.54 GiB / 卡；1 GiB 显存约 5,084 页 ≈ 65 万 token。真正占地方的是并发：每个在途请求 2.62 MiB 的 STATE 与上下文长度无关。

STATE

一个槽 = 40 层窗口 + 两份 compressor 尾巴 + 一个游标

state_fields（atom/model_ops/attentions/pool_layout/v41_pool_geometry.py:334）定义一个在途请求的全部私有状态。槽数是 max_num_seqs， 请求进来从空闲表拿一个，结束时还回去。槽里的东西都与历史长度无关，只与「最近」有关。

每个字段对齐到 8,448 B（528 与 256 的最小公倍数）后，一个槽是 2,745,600 B ≈ 2.62 MiB = 5,200 个 528 B 行。开 DSpark 5 个投机 token 时，窗口变成 [43, 133, 528]（多 3 个草稿层、每层多 5 个槽），尾巴变成 [4, 7, 512]，一个槽约 3.0 MiB（估算）。max_num_seqs = 64 时 STATE 总共约 168 MiB。

尾巴为什么不进镜像

镜像只打在页边界上，128 是 ratio 1 和 2 的公倍数，边界上没有凑了一半的组，恢复后第一个要读的组正好由恢复后的 forward 自己写。

寻址

所有读写最后都是 pool 里的一个行号

全局行：逻辑行号 s 先除以每页行数得到块表的列，查块表得到物理页，再加 owner 在页内的偏移。index 行按 tile 寻址，每 tile 8 行。 窗口行不经过块表：槽号 × 每槽行数 + 第 L 层 ring 的起点 + pos % ring_slots（atom/model_ops/v4_kernels/pool_index.py:63）。

前缀缓存

命中的页直接挂进新请求的块表，STATE 每次都重建

一页就是一个 hash 块。块 k 的 hash 链式依赖块 0 … k 的全部 token，所以命中只能是从第 0 块起连续的一段。 又因为一个 block id 同时指 4 个 owner 的主 latent 和 index 行，一次命中就把 4 份全局 KV 一起复用了。

  1. 准入（can_allocate，atom/model_engine/block_manager.py:1163）：沿 hash 链从第 0 块往后找，第一次不命中就停。 最后一块永远不复用——prefill 至少要算一块才能出 logits。然后过一道 STATE 门：replay 模式下任何边界都接受（atom/model_engine/state_pool.py:461 直接返回原命中）； checkpoint 模式下只能退到存过镜像的边界。
  2. 分配（allocate，atom/model_engine/block_manager.py:1632）：命中的页引用计数 +1，挂进块表前几列；其余列从空闲表取新页； 再从 STATE 空闲表取一个新槽。
  3. 前向：replay 模式下从命中点往前退一页（replay_start，atom/model_engine/block_manager.py:1847）重建新槽里的窗口， 这一段只读命中的页、不往里写；命中点之后正常写新页。完整流程见第 11 章。
  4. 登记：forward 之后 hash_blocks 只登记本次写满、且在重放起点之后的块；命中的那些块本来就登记过。
  5. 释放与淘汰：请求结束时引用计数 −1，STATE 槽直接还回去（replay 模式不保留）。引用归零的页带着 hash 留在空闲表里， 仍能被命中，直到被一次新分配取走才失效（on_evict）。

例子 · 图 5 的数字怎么来

A 的 prompt 1000：块 0–6（0–895）写满已登记，块 7 还没写满。B 前 800 个 token 与 A 相同：块 0–5（0–767）hash 全同，块 6（768–895）在 800 处分叉。 命中 6 块 = 768 token；B 的块表前 6 列指向 A 的页 [41, 7, 93, 12, 58, 3]，各自 ref = 2；B 另取 4 页给块 6–9。 B 的 forward 从 768 − 128 = 640 开始，640–767 读 A 的页但不写；之后块 6–8（768–1151）写满并登记，块 9 还差 80 个 token。

复用了什么

4 份全局 KV + 4 份 index

main_2/8/14/20 与它们的 index 行同属一个 block id，命中一页就是 4 个 owner 的 128 个 token 全部到手。

没复用什么

窗口、尾巴、游标

STATE 从不在请求之间共享：replay 模式下重算（多算 128 行 encoder），checkpoint 模式下按字节从镜像拷回。

粒度

命中只落在 128 的倍数上

不足一页的公共前缀复用不了；这也是插件路径 PAGE = 256 时复用变粗的原因。

卸载与插件

搬出卡外的单位也是页；插件路径把整块池借给 vLLM 管

lmcache_mp

按 PAGE 单元发布

get_kv_transfer_tensors（atom/model_ops/attentions/deepseek_v41/backend.py:444）把一个 block id 的所有区域——4 个主字段与各 owner 的 index 行——作为一个单元交给连接器。 replay 模式下只搬 PAGE，层里取回来的命中按 HBM 命中同样往前退一页重算（tier_resume_replays）；checkpoint 模式下 STATE 镜像也存在 PAGE 单元里一起搬， 一个镜像约占 13 个单元（atom/model_engine/page_unit_checkpoint.py:64，估算）。

vLLM 插件

一个假注意力层当字节 arena

插件声明一个 FullAttentionSpec 的假层让 vLLM 按块分配，块大小强制为 256（atom/plugin/vllm/deepseek_v41_bridge.py:60），vLLM 的块号就是页号； STATE 用块池尾部的若干块买下来，再告诉 KV 管理器不要分出去。插件路径不支持前缀缓存：vLLM 假设每个缓存块边界都有可恢复的状态，V4.1 给不出（第 11 章末）。
