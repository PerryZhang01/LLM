Reuse 层

40 层里有 30 层是 REUSE：它们没有 Compressor，也没有 Indexer，全局 KV 和 top-k 选择都借组首层的。 但它们仍然有自己的 query、自己的窗口 KV、自己的输出投影，所以同一组里的几层看到同一批全局行，算出来的东西却各不相同。 这一章讲 REUSE 层还剩哪些计算、下标组怎样一次生成给整组用，以及它和 FULL 层差了多少算力。

30REUSE 层（encoder 15 + decoder 15）
5 / 8A–H 里自己跑的步数
0F 步启动的 kernel 数
640每 token 的 key 数（512 + 128）
≈ 337MFLOP / token / 层（估算）
≈ 44%相对 FULL 层（L=100k，估算）

范围

既不是 KV owner、也不是 index source 的层，全是 REUSE

build_attention_topology 给每一层定模式时只问两件事：这一层是不是 KV source（是就是 FULL），是不是 index source（是就是 REINDEX）； ratio 非 0 且两样都不是，就是 REUSE（atom/models/deepseek_v41/config.py:137）。Flash 上一共 30 层：

checkpoint 里 REUSE 层本来就没有 compressor.* 和 indexer.* 张量：schema 只给 FULL 层列 compressor 与 indexer.wk， 只给 FULL 和 REINDEX 列 indexer.wq_b / weights_proj（atom/models/deepseek_v41/weights.py:166、atom/models/deepseek_v41/weights.py:179）。 建模块时也一样：atom/models/deepseek_v41/attention.py:290 起两行决定 self.compressor 与 self.indexer 是不是 None。

一层的路径

A、B、C、G、H 自己跑；D、E 没有；F 只是取一份现成的下标

第 4 章把一层 CSA2 拆成 A–H 八步。REUSE 层走的是同一个 Attention.forward（atom/models/deepseek_v41/attention.py:402）， 只是其中两步碰到 None 就直接返回：_compress_batch 在 self.compressor is None 时返回（atom/models/deepseek_v41/attention.py:310）， _fork_select 在 self.indexer is None 时什么都不做。

  1. A：wqkv_a 一次 FP8 GEMM 出 q_lora [T,1280] 和 kv [T,512]，DualRMSNormMXFP8 一次 launch 出 qr 和 kv_normed。
  2. B：wq_b(qr) → q [T, 64, 512]，TP4 下每卡 16 头。
  3. C：rope_quant_window 转 q 与 kv 的最后 64 维，kv 量化成 528 B 的 MXFP8 行；decode 时直接写进本层 ring，prefill 时留到 attention 之后。
  4. F：拿组首层建好的下标。prefill 拿 prefix[layer − first]（专属本层的一份），decode 拿全组共用的 prefix[0] 和 window_rows。
  5. G：双源稀疏注意力，源 1 是 owner 池里被选中的 ≤512 行，源 2 是本层窗口的 ≤128 行，加 sink 一起 softmax。
  6. H：inverse RoPE + MXFP8 量化 → wo_a 8 组 × (4096 → 1024) → wo_b 8192 → 5120，TP all-reduce。

下标组

组首层一次把整组的下标建好，因为组首层正是做选择的那一层

_tag_index_groups 把 (ratio, kv_owner, topk_owner) 都相同的连续层归成一组（atom/models/deepseek_v41/config.py:155）。 这样分组有一个好处：组里第一层就是 topk_owner 本身——它的 Indexer 刚刚写完 step.selected[owner]， 同一层的 F 步紧接着就能把整组的下标建出来。attention_indices 的文档原话是 “Later layers find theirs written and launch nothing.”

prefill

每层一份 prefix，extend 共用

prefix 里是「选中的全局行 + 本层 ring 里本 chunk 起点之前的窗口行」，后一部分按层错开一个 stride；extend 是本 forward 自己的 KV 行，6 层的行号一样，只写一份。 prefix 的总长是 layers × T × (512 + 128)（plane = step.width × (topk + window_size)）。

decode（split）

选择一份、窗口行号一份

窗口全部已经在 ring 里，所以不必为每层拷一份行号：build_window_rows 按组首层的 ring 生成一张相对行号表（atom/model_ops/attentions/deepseek_v41/indices.py:345）， 每层调用 attention 时传自己的 ring_view(layer) 作基址（atom/model_ops/attentions/deepseek_v41/cache.py:942）。

对照

encoder 的 REUSE 每段换一份 KV；decoder 的 REUSE 一直读同一份

同样叫 REUSE，两段的处境不同。encoder 的三段各有自己的 owner 和自己的压缩 KV，下一段开始时整份换掉； decoder 的 15 个 REUSE 层全部读 main_20，只是每 4 层换一次选择——第 20 层全量选一次，第 24、28、32、36 层在候选块里各重选一次（第 9 章）。

例子

第 5 层在位置 5000 看到 640 个 key，其中 512 个和第 2 层完全相同

例子 · decode，t = 5000，组 [2, 8)

  1. 第 2 层的 Indexer 对 main_2 的可见行打分：visible = (5000 + 1) // 2 = 2500 行，选出 512 行，写进 selected[2]。
  2. 第 2 层的 F 步建好整组的下标：一份选择平面（512 个压缩行号），一张窗口行号表（位置 4873–5000 共 128 行，相对 ring 起点）。
  3. 第 5 层跑完自己的 A、B、C：用自己的 wq_b 出 query，把自己在位置 5000 的 KV 写进自己的 ring。
  4. 第 5 层的 F 直接取那两张表；G 步读 main_2 的 512 行 + 自己 ring 的 128 行，一共 640 个 key，再加一个 sink。

512 个压缩行每行覆盖 2 个 token，所以这 640 个 key 大约代表 1024 + 128 个位置的信息。

算力

长上下文下，REUSE 层不到 FULL 层的一半

REUSE 层省掉的是 Compressor 的 GEMM、index query 投影和对全部可见行的打分。前两样是常数，第三样随上下文线性增长， 所以上下文越长，REUSE 相对 FULL 越便宜。下图按形状估算了 L = 100,000 时 decode 一个 token 在一层上的乘加量。

省下的

D、E 两步

compressor wkv_gate 5120→1024、wk 512→128、indexer.wq_b 1280→4096、weights_proj 5120→32，以及打分与 top-k。

还在的

投影与注意力

每层都有自己的 Q/KV 下投影、query 上投影、640 个 key 的注意力和输出 LoRA，这部分与 FULL 层完全一样。

代价

同组看到同一批历史

同组 6 层（或 4 层）的远处信息都是同一组 512 行；区别只来自各层不同的 query 和窗口。decoder 用 REINDEX 每 4 层重选一次来缓和这一点。

  2. atom/models/deepseek_v41/attention.py:290：REUSE 层的 compressor 与 indexer 都是 None。

读码坑

「REUSE 层不做 F」并不准确：它调用了 attention_indices，只是命中缓存、不启动 kernel。 bounded replay 里第 39 层的 query 少于 KV 行，QueryRows.indices 会传一个 group_indices={} 的副本强制重建（第 11 章），那是唯一不复用组下标的地方。
